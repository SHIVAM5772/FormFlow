# Capabilities and explicit limits

This is a functional implementation with conservative fallbacks, not a promise that every Google Form layout is automatable. The complete chain is implemented: analyze → versioned schema → dynamic Excel → validate → explicit authorization → durable batch → browser submission → verification → report. Live third-party Google compatibility has not been tested in this environment.

| Capability                    | Behavior                                                                                                                                                                                                                                                                                                                                                                                           |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Public URLs                   | Exact HTTPS `docs.google.com/forms/.../viewform` or `/edit`, and `forms.gle` links. Redirects remain on allowlisted Google hosts. Prefilled links, response-edit tokens and arbitrary query parameters are rejected.                                                                                                                                                                               |
| Public analysis               | Playwright reads rendered respondent metadata and restriction text. Metadata is undocumented and validated; unknown layouts produce an error or blocker. No answer is submitted during analysis.                                                                                                                                                                                                   |
| Owner analysis                | OAuth read-only Forms API normalizes text, choices, scales, grids, dates, times, page breaks and choice-based navigation for accessible forms. The app accepts the returned respondent URL, not a user-supplied API host.                                                                                                                                                                          |
| Short / paragraph             | Supported through textboxes. Identifier columns are text-formatted.                                                                                                                                                                                                                                                                                                                                |
| Radio / dropdown / checkboxes | Supported with exact option labels. Checkboxes use `;` separators. Labels containing `;` block that form. Repeated choices and unrecognized options are invalid.                                                                                                                                                                                                                                   |
| Other                         | `Other: your text` is accepted when the analyzed choice supports Other. Browser mapping must be unambiguous; otherwise manual action.                                                                                                                                                                                                                                                              |
| Linear scales                 | Integer limits and choices are validated. Radio controls must expose exact numeric labels.                                                                                                                                                                                                                                                                                                         |
| Grids                         | One Excel column per grid row. Browser mapping requires an accessible named radiogroup or identifiable row. Unrecognized Google grid accessibility layouts pause the batch.                                                                                                                                                                                                                        |
| Dates / times                 | Calendar-valid ISO `YYYY-MM-DD` and 24-hour `HH:mm` text; native controls and English Google component controls. Duration, date+time combined questions and dates without a year need manual handling.                                                                                                                                                                                             |
| Required / conditional fields | Validation follows a deterministic section path and applies required rules only there. Simple owner-API choice branches and sequential sections are supported. Public conditional metadata is flagged rather than inferred.                                                                                                                                                                        |
| Multiple sections             | Browser visits only sections that expose known questions. Empty/title-only sections, repeated sections, cycles, section-level jump metadata not exposed by the API, ambiguous navigation, and shuffled layouts may require manual action. Branches that submit through a Next button are refused; an explicit Submit button is required.                                                           |
| Custom response validation    | Public metadata indicating validation blocks automation. Unknown server-side validation may reject a row. The app does not promise to reproduce regex/text/number limits that are unavailable through the API.                                                                                                                                                                                     |
| Email collection              | API configuration and known public respondent notices are detected and blocked for identity review. Unrecognized notices may be missed, so review the form preview yourself.                                                                                                                                                                                                                       |
| Sign-in / organization access | Known English restrictions and account redirects are detected. Fresh anonymous respondent contexts never receive stored OAuth credentials. Restricted forms are unsupported for automated submission.                                                                                                                                                                                              |
| File uploads                  | Detected and blocked; no automatic upload, password prompt or sign-in workaround.                                                                                                                                                                                                                                                                                                                  |
| CAPTCHA / response limits     | Detectable CAPTCHA widgets and notices pause the affected batch. No bypass, stealth evasion, proxies or limit circumvention. Invisible/reworded restrictions may instead cause manual action, failure or UNKNOWN.                                                                                                                                                                                  |
| Response editing              | Capability is explicitly unknown (`null`); no response-edit workflow or edit-token storage exists.                                                                                                                                                                                                                                                                                                 |
| Closed forms                  | Common English closure/deletion notices are detected. Other languages may cause a conservative analysis/submission failure.                                                                                                                                                                                                                                                                        |
| Confirmation                  | A successful respondent POST reply (including normal redirects), exact expected confirmation text, and no visible Submit button are required. Custom text is read from publicly delivered form settings; known default English messages are a fallback. Unknown messages, errors or missing confirmation stay UNKNOWN. This is browser verification, not an independent owner Responses API audit. |
| Retry                         | Explicit user retry is available for FAILED/no-intent rows and known question-mapping failures with no intent. UNKNOWN, submitted, intent-bearing and other manual-action records are refused. Resume only continues queued rows.                                                                                                                                                                  |
| Duplicate prevention          | Duplicate rows in the same upload are invalid; identical validated content uploaded under the same user/template reuses the existing upload; starting a batch for that upload is idempotent. Identical data in a deliberately new template/batch is not globally deduplicated because repeated real responses can be intentional.                                                                  |
| Pause/resume/cancel           | Stored per batch, checked between steps and atomically when writing intent. Already-clicked responses can still finish after cancellation. Resume continues queued rows; it does not silently retry manual-action or UNKNOWN records.                                                                                                                                                              |
| Recovery                      | An interrupted RUNNING row becomes UNKNOWN on queue redelivery, even if a missing intent might suggest it was safe. This deliberately sacrifices some automatic recovery to protect against duplicates.                                                                                                                                                                                            |
| Reports                       | XLSX validation and submission reports contain row numbers, status, attempts, timestamps and error reasons. Answers are omitted by design.                                                                                                                                                                                                                                                         |
| Authentication                | Admin-provisioned password accounts, bcrypt hashes and revocable signed sessions. No public signup, password reset email, MFA or enterprise identity provider is included.                                                                                                                                                                                                                         |
| Retention                     | Explicit user deletion; scheduled CLI removes expired uploads/batches and audit events, excluding active jobs. Schemas remain until user deletion.                                                                                                                                                                                                                                                 |
| Scaling                       | One API instance with process-local limits, one sequential worker by default. Multiple workers are configurable but increase total load. No cross-replica Socket.IO adapter or distributed rate limiting is included.                                                                                                                                                                              |

## Google API boundary

Public short-answer questions with the recognized standard Google Email validation rule are normalized as email fields and validated during upload and submission. Unknown or combined custom rules remain blockers. An ordinary email-answer question is separate from automatic/verified Google email collection; supporting its syntax does not grant respondent sign-in access. Reanalyze to create a schema version containing the recognized rule, then generate a new matching template.

The official Forms API can read a form body for users who have appropriate access; its responses resource offers read methods, not a bulk respondent-create method. Accordingly, this project uses the API for owner analysis and Playwright for authorized respondent submissions. OAuth read access does not authorize bypassing Google's respondent restrictions. See [Google's REST reference](https://developers.google.com/workspace/forms/api/reference/rest).

## Remaining validation work

A sign-in restriction can coexist with publicly delivered question metadata. In that case the analyzer can display the title/questions and generate a review template while preserving the submission blocker. If metadata is unavailable, empty template downloads are refused. Reanalyze a public form after its owner updates access settings; a preview is not proof that anonymous submission is permitted.

Before real operational use, validate a form you own covering your exact question types, navigation, locale and validation rules; confirm saved responses in the owner's Responses section. Run the MongoDB integration suite and verify the Vercel deployment with your configured Atlas database. The browser integration tests use only the included local HTML fixture.
