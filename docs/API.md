# REST API

Base path `/api`. Signup request, resend, verification, login and health do not require a session. Other workspace routes require the HttpOnly `session` cookie issued by successful OTP verification or login; the scheduled worker endpoint uses its separate cron secret. All POST/DELETE/PATCH/PUT requests must supply an `Origin` header exactly matching `WEB_ORIGIN`; browser Axios requests do so automatically. Cookie credentials are required. Success is `{ "data": ... }`; errors are `{ "error": { "code": "...", "message": "..." } }`. UUID path/body identifiers are validated. Lists are scoped to the current account.

Development-only exception: when `WEB_ORIGIN` uses `localhost` or `127.0.0.1`, either hostname is accepted on the same configured protocol and port. CORS, mutation checks and Socket.IO use this same exact allowlist. Production and test mode accept only the configured origin; arbitrary ports, LAN addresses and external origins are not added.

Typical errors: 400 invalid input/upload, 401 missing/expired session, 403 Origin mismatch, 404 unowned/missing object, 409 invalid lifecycle/template state or concurrent duplicate, 422 unsupported form/workbook, 429 rate/resource limit, 500 unavailable dependency/internal error. Multer limits compressed bytes; ZIP and row validation enforce further limits. XLSX error responses are JSON; clients should inspect failed downloads before assuming the payload is a workbook.

The schema states are `PENDING`, `VALIDATING`, `QUEUED`, `RUNNING`, `SUBMITTED`, `FAILED`, `UNKNOWN`, `NEEDS_MANUAL_ACTION`, `CANCELLED`. Uploaded validation rows are represented separately until authorized; only valid rows become submission records. Job states are `QUEUED`, `RUNNING`, `PAUSED`, `COMPLETED`, `CANCELLED`; COMPLETED means processing has ended and may include failed or unknown outcomes.

## Real-time progress

Socket.IO at `/socket.io` uses the same session cookie and exact allowed Origin. The server joins only the authenticated user's room. `job:updated` emits `{jobId}` as an invalidation event; retrieve current job/records via REST. The UI also polls, so missing events are recoverable. No response answers are emitted.

Next.js uses HTTP polling through a rewrite preserving the API's `/socket.io/` endpoint. Same-origin browser polling GETs without Origin require `Sec-Fetch-Site: same-origin`; namespace authentication still applies. Explicit foreign Origins are rejected.
